# Private relay

Requires Python 3.11+. Install `pip install -r relay/requirements.txt`.
Inject these variables using your service manager/secret manager (never commit a `.env`):

- `NOVEL_API_KEY`: provider key.
- `NOVEL_API_BASE`: HTTPS OpenAI-compatible base URL, e.g. ending in `/v1`.
- `NOVEL_MODELS`: comma-separated permitted model IDs.
- `RELAY_PAIRING_CODE`: random one-use code, minimum 16 characters. Rotate after pairing or device loss.
- `RELAY_ENCRYPTION_KEY`: persistent Fernet key generated by `Fernet.generate_key()`; retain securely across restarts.
- `RELAY_DB`: database path on an encrypted persistent volume (default `./relay-data/relay.sqlite3`).
- Optional `NOVEL_PRICES_JSON`: model-to-price mapping, e.g. `{"model-id":{"input_per_million":1,"output_per_million":2,"currency":"USD"}}`.

Run `uvicorn relay.app:create_app --factory --host 127.0.0.1 --port 8081 --no-access-log`.
Use one server process. Put it behind an HTTPS reverse proxy with body limit 2 MiB,
rate limits on pairing, and no request/response-body logging. Never expose plaintext HTTP.
Pair from APK using the relay HTTPS URL and the one-use code, not the provider key.
The app stores a device credential protected with Android Keystore.

Prompts are held in memory only. Responses are Fernet-encrypted, removed within
24 hours plus a 60-second cleanup interval. Request tombstones prevent replays
from causing another charge after expiry. SQLite and encrypted-volume backups
must follow your retention policy (SQLite page deletion alone is not secure erasure).

A timeout or relay process death produces UNKNOWN: no automatic replay to the
provider. Check the provider's ledger before resolving it. To revoke a device,
stop the service and delete its row from `device`; rotate the pairing code to pair again.
This version intentionally does not expose a remote administrative override for UNKNOWN.
No provider calls or deployment are performed by the test suite.

For an UNKNOWN outcome, stop the relay and confirm the outcome in the provider's
ledger. Then use `python -m relay.admin REQUEST_ID --not-completed --reason 'operator note'`
or `--response /private/recovered-completion.json` with the actual provider response.
Restart the relay and resume in the APK to retrieve the reconciled outcome. A
confirmed failure can then be retried explicitly. This does not waive any QA gate.
